# Пайплайн каталога рецептов и генерации данных (WhatCook Recipe Pipeline)

Документ описывает архитектуру обработки кулинарных данных, роль нейросетей (Sber GigaChat и FLUX.1), структуру датасета и механизмы работы фонового сервиса `RecipeWorker`.

---

## 1. Архитектурная эволюция

* **Ранняя концепция (Архив)**: Первоначально рецепты импортировались из англоязычного API TheMealDB и переводились через машинные переводчики (Google Translate / Groq LLM). Этот подход приводил к неестественным названиям блюд, расплывчатым формулировкам шагов и частым превышениям лимитов токенов (TPM/RPM).
* **Текущая архитектура**: Полный переход на аутентичный русскоязычный кулинарный датасет (`russian-recipes-parser`), глубокую нормализацию через Sber GigaChat и генерацию ресторанных обложек нейросетью FLUX.1 с локальным хранением и сжатием изображений.

---

## 2. Источник кулинарных данных

* **Датасет**: Репозиторий `chipslays/russian-recipes-parser`.
* **Формат хранения**: Шардированные JSON-файлы по подпапкам:
  ```text
  storage/recipes/{folder}/{id}.json
  ```
  где `id` начинается со `100001`, а номер папки рассчитывается как `folder = id / 1000` (например, `storage/recipes/100/100001.json`).
* **Отказоустойчивость**: Функция `CandidateRecipeURL` формирует валидные пути, а логика парсера допускает пропуски идентификаторов (воркер завершает чанк только при фиксации более 50 последовательных ответов 404 Not Found).

---

## 3. Семантическая нормализация (Sber GigaChat API)

Для каждого нового рецепта Sber GigaChat выполняет нормализацию структуры:
1. **Канонизация ингредиентов**: Приведение сырых строк к нормализованным названиям в нижнем регистре (например, `«куриное филе охлажденное»` -> `«куриное филе»`).
2. **Критичность ингредиентов**: Разметка каждого продукта по шкале важности для алгоритма умного сопоставления:
   * `основной` — ключевой компонент блюда (мясо, рыба, крупа), без которого блюдо невозможно приготовить;
   * `важный` — существенно влияющий на вкус (сыр, лук, соус);
   * `опциональный` — специи, зелень для подачи, которые можно опустить.
3. **Расчет времени и сложности**: Вычисление реалистичного времени готовки (в диапазоне от 15 до 240 минут) и категории сложности (`легко`, `средне`, `сложно`).
4. **Гастрономический промпт (`image_prompt`)**: Составление детального описания блюда на английском языке в ресторанной стилистике для генератора изображений (освещение, подача, ракурс, текстура).

---

## 4. Генерация и оптимизация обложек (FLUX.1 + OptimizeRecipeImage)

1. **Генерация**: Метод `GenerateFluxImage` отправляет сформированный `image_prompt` в нейросеть FLUX.1 Schnell.
2. **Детерминированное именование**: Имя файла формируется на основе SHA-256 хэша от канонического названия блюда (`RecipeImageFilename`). Это гарантирует отсутствие дублей на диске при повторных прогонах.
3. **Встроенная оптимизация (`backend/internal/storage/storage.go`)**:
   * Без внешних тяжелых CGO-библиотек: чистый алгоритм билинейного масштабирования до разрешения 512x512 пикселей.
   * Сжатие в формат JPEG с качеством 75 (Quality 75).
   * Снижение веса файла с ~400–800 КБ до ~25–45 КБ (>65% экономии диска без потери визуального качества на смартфонах).
4. **Раздача**: Файлы сохраняются в директорию `backend/uploads/recipes/`, раздаются Gin по маршруту `/uploads` и прозрачно проксируются Vite во время разработки.

---

## 5. Фоновый воркер `RecipeWorker`

Сервис `RecipeWorker` (`backend/internal/service/recipe_worker.go`) работает как автономный фоновый процесс в Go:
* **Лимиты и батчинг**: Загрузка рецептов чанками по 50 штук с целевым объемом базы до 500 рецептов.
* **Троттлинг**: Обработка рецептов мини-пачками по 3 штуки с паузой 1 минута между ними для предотвращения блокировок со стороны внешних API.
* **Управление квотами**: При получении статуса 429 (Rate Limit) воркер автоматически приостанавливает работу на 10 минут, логируя состояние в Docker.
* **Graceful Fallback**: При временной недоступности нейросетей воркер использует курируемую кулинарную базу проверенных изображений блюд (`GetCuratedRecipeImage`).

---

## 6. База данных и стартовый сид

* **Миграция `000003_seed_recipes.up.sql`**: Содержит 50 готовых аутентичных блюд русской кухни (супы, горячее, выпечка, десерты, салаты).
* **Связи**: Все рецепты содержат полную структуру ингредиентов с привязкой к таблице `ingredients` и локальными путями к обложкам `/uploads/recipes/...`.
* **Полнотекстовый поиск**: База поддерживает быстрый морфологический поиск по названиям рецептов и ингредиентов через PostgreSQL GIN-индекс `tsvector` (`to_tsvector('russian', ...)`).
