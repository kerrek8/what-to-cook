# Перевод рецептов

Backend загружает рецепты из TheMealDB в PostgreSQL и ставит их в очередь перевода. Фоновый обработчик переводит название, описание, шаги, ингредиенты и меру ингредиентов, затем сохраняет русский текст в БД. Ошибки повторяются с экспоненциальной задержкой.

Архитектура переводчика (`TranslationService`):
1. **Кулинарный словарь в памяти**: для популярных продуктов и поисковых запросов («соль», «курица», «оливковое масло» и др.) перевод выполняется мгновенно без сетевых обращений.
2. **Проверка целевого языка**: если текст уже написан на целевом языке (русские символы при переводе на русский), внешний запрос не отправляется.
3. **Прямой Google Translate Web API**: с браузерным User-Agent и таймаутом.
4. **Резервный провайдер MyMemory API**: автоматический fallback при ошибках или 429 от Google.
5. **Резервный провайдер gtranslate**: дополнительный fallback в случае сбоя первых провайдеров.

API каталога возвращает только рецепты со статусом `translated`. Поле `pending_translations` показывает число рецептов, которые ещё обрабатываются или ожидают повторной попытки. Пока очередь работает, фронтенд периодически обновляет каталог. Поиск в TheMealDB добавляет найденные блюда в БД; они становятся видимыми после завершения перевода.

При старте каталог наполняется запросами по популярным группам блюд, если в базе меньше 120 рецептов. Это расширяет существующую базу после обновления.

Перед запуском новой версии нужно применить миграции:

```sh
migrate -path backend/migrations -database "$DATABASE_URL" up
```

Для локальной проверки endpoint перевода и поиска:

```sh
curl -X POST http://localhost:8080/api/v1/translations \
  -H 'Content-Type: application/json' \
  -d '{"texts":["Chicken"],"source":"en","target":"ru"}'

curl -X POST 'http://localhost:8080/api/v1/recipes/sync?q=chicken'
curl 'http://localhost:8080/api/v1/recipes?limit=20'
```
