# Полный редизайн WhatCook по макету Figma и поэтапный отказ от Vant UI

- **Дата**: 2026-11-18
- **Статус**: Готов к утверждению (Brainstorming Design Doc)
- **Стек**: Vue 3 (Composition API, `<script setup>`, TypeScript), Vite, Bun, Tailwind CSS, Lucide Icons, Pinia, Dexie.js (IndexedDB), Vitest.

---

## 1. Контекст и цели (Intent & Why)

### 1.1. Проблема
Текущий интерфейс приложения WhatCook опирается на библиотеку мобильных компонентов **Vant UI**. На практике использование Vant UI показало следующие недостатки:
1. **Сложность стилизации и переопределения**: компоненты Vant имеют жесткую структуру DOM и сильные предустановленные стили (синяя палитра, фиксированные границы ячеек, отступы). Кастомизация каждого элемента под уникальный дизайн требует десятков переопределений CSS-переменных и селекторов `::v-deep`.
2. **Лишняя зависимость**: библиотека не дает уникальных преимуществ для MVP, утяжеляет бандл и ограничивает гибкость.
3. **Несоответствие новому визуальному языку**: в макетах Figma разработан целостный, современный кулинарный стиль с глубоким изумрудным дашбордом, пресетами сроков годности и специализированным темным режимом готовки (Cook Mode), который на чистом Tailwind CSS реализуется быстрее, чище и прозрачнее.

### 1.2. Цели
1. **Полное визуальное соответствие макету Figma**: переработка всех экранов приложения в единой изумрудно-зеленой палитре (`#064E3B`, мятные акценты, мягкие тени, скругленные карточки, чистая мобильная типографика).
2. **Полный отказ от Vant UI**: замена всех компонентов `van-*` на собственные легковесные компоненты на базе **Tailwind CSS + Lucide Icons + Vue 3 `<Transition>`**.
3. **Сохранение 100% бизнес-логики и офлайн-возможностей**: архитектура Pinia + Dexie.js (IndexedDB), Service Worker (PWA), интеграция с Go REST API остаются неизменными.
4. **Сохранение надежности**: все 89 существующих модульных тестов Vitest должны оставаться зелеными (с адаптацией под новую верстку).
5. **Финальная верификация удаления**: полное удаление пакета `vant` из `package.json`, отсутствие любых упоминаний и стилей Vant в бандле.
6. **Актуализация документации и финальный отчет**: компактификация `README.md` и развернутый отчет о результатах работы.

### 1.3. Не-цели (Non-Goals) и анти-цели
* **Не-цель**: Переписывание приложения на React (отклонено — остаемся на Vue 3).
* **Не-цель**: Изменение бэкенд API или схемы PostgreSQL (все DTO и эндпоинты остаются 100% совместимыми).
* **Не-цель**: КБЖУ (калории, БЖУ) и категории блюд (завтрак, обед, ужин) в рецептах: в базе данных этих полей нет, искусственные моки не создаются, отображаются только реальные проверенные данные (время, сложность, ингредиенты, процент совпадения).
* **Не-цель**: Физические места хранения («Холодильник / Морозилка / Шкаф»): в схеме данных и синхронизации с сервером продукты делятся по категориям ингредиентов. Фильтры дашборда работают по категориям и сроку годности, гарантируя сохранность данных в облаке.
* **Не-цель**: Выход за рамки скоупа MVP (никаких сложных распознаваний чеков, сканеров штрихкодов или семейных аккаунтов).
* **Анти-цель**: «Большой взрыв» (одномоментное вырезание Vant из всех файлов сразу), парализующий работоспособность проекта. Переход выполняется строго поэтапно, экран за экраном.

## 2. Сравнительный анализ подходов (Approaches)

### Подход 1: Инкрементальный редизайн на Tailwind CSS с поэтапной заменой Vant (Выбранный)
* **Суть**: Мы движемся экран за экраном (Холодильник -> Шторка добавления -> Рецепты -> Детали рецепта и Cook Mode -> Покупки -> Профиль). Каждый обновленный экран пишется с нуля на чистом Tailwind CSS без единого компонента Vant. На финальном этапе пакет `vant` деинсталлируется из `package.json`.
* **Плюсы**: проект непрерывно находится в рабочем состоянии, тесты проходят на каждом шаге, минимальный риск регрессий.
* **Минусы**: на промежуточных этапах в проекте временно сосуществуют новые Tailwind-компоненты и еще не обновленные экраны на Vant.

### Подход 2: Полный рерайт на React
* **Суть**: Создание нового фронтенда на React + Next.js / Vite.
* **Почему отклонен**: Требует переписать ~4000 строк кода, сторы Pinia, офлайн-хуки Dexie, PWA-манифест и 89 тестов. Затраты 2-3 недели при нулевой добавленной функциональности для пользователя.

### Подход 3: Глубокая кастомизация Vant UI через переменные тем
* **Суть**: Оставить Vant и переписать `:root { --van-... }`.
* **Почему отклонен**: Не решает проблему жесткой структуры DOM Vant, затрудняет реализацию уникальных элементов из Figma (дашборд со сводкой, быстрые чипы пресетов, темный экран таймера), оставляет проект зависимым от чужой библиотеки.

## 3. Архитектура дизайн-системы и замена примитивов Vant

### 3.1. Палитра и токены (Tailwind)
* **Primary Emerald**:
  * `emerald-950` / Deep Forest: `#064E3B` (шапка, фон дашборда, активные акценты).
  * `emerald-700`: `#047857` (основные кнопки, бейджи высокого совпадения).
  * `emerald-500`: `#10B981` (индикаторы свежести, успешные действия).
  * `emerald-50`: `#ECFDF5` (фоны бейджей, карточки ингредиентов в наличии).
* **Warning & Expiry**:
  * `amber-500` / `amber-50`: предупреждение (срок < 3 дней).
  * `rose-500` / `rose-50`: просрочено.
* **Neutral**:
  * Фон приложения: `#F8FAFC` (Slate-50) или чистый бело-серый.
  * Карточки: `#FFFFFF` с мягкой тенью `shadow-sm` и скруглением `rounded-2xl`.
  * Cook Mode: темный фон `#0F172A` / `#022C22` с контрастным белым текстом.

### 3.2. Матрица замены компонентов Vant

| Компонент Vant | Альтернатива без Vant | Реализация |
|---|---|---|
| `van-button` | `<button class="w-full py-3 px-4 rounded-xl font-medium bg-emerald-700 text-white ...">` | Чистый Tailwind |
| `van-tabbar`, `van-tabbar-item` | `AppTabBar.vue` | Фиксированная нижняя панель на Tailwind + `lucide-vue-next` + safe-area |
| `AppHeader` / `van-nav-bar` | `AppHeader.vue` | Кастомная шапка с поддержкой слотов, иконок и глубокого изумрудного фона |
| `van-action-sheet`, `van-popup` | `BaseBottomSheet.vue` | Vue `<Transition>` + `Teleport to="body"` + backdrop + swipe-down gesture |
| `van-swipe-cell` | `ProductCard.vue` / `ShoppingItemCard.vue` | Тап по карточке открывает контекстное меню («Изменить / Удалить») + нативный легкий `useSwipe` |
| `van-date-picker` | Пресеты сроков + Нативный `<input type="date">` | Быстрые чипы (+3д, 1 нед, 2 нед, Заморозка) + нативный input |
| `van-pull-refresh` | Нативный pull-down или CSS `overscroll-behavior` | Легковесный хук тача |
| `van-toast`, `van-dialog` | `useToast()` / `BaseDialog.vue` | Легкий Pinia-стор уведомлений и модальных подтверждений |
| `van-tabs`, `van-tab` | `BaseSegmentedControl.vue` / Чипы фильтров | Горизонтальный скролл пиллс-кнопок на Tailwind |
| `van-field`, `van-cell` | `BaseInput.vue` / Tailwind inputs | Семантичные `<input>` с лейблами, подсказками и ошибками |

## 4. Поэтапный план реализации

### Фаза 1: Фундамент дизайн-системы, нижний таббар и экран «Холодильник»
1. **Токены и базовые компоненты**:
   * Настройка кастомных цветов изумрудной палитры в `tailwind.config.js`.
   * Создание легковесного `AppTabBar.vue` на чистом Tailwind + `lucide-vue-next` (с безопасными зонами iOS/Android).
   * Создание простого сервиса уведомлений `useToast` (всплывающие подсказки без `showToast` из Vant).
2. **Изумрудный дашборд сводки (Холодильник)**:
   * Верхний hero-блок: сводная статистика инвентаря (всего позиций, истекают скоро, просрочено).
   * Быстрый фильтр в стиле пилюль Figma: `[Все]`, `[🔥 Истекают]`, `[Молочные]`, `[Овощи]`, `[Мясо]` (фильтрация по реальным категориям без ломки бэкенда).
3. **Новые карточки продуктов (`ProductCard.vue`)**:
   * Верстка на Tailwind: иконка/эмодзи категории, название, количество, статус свежести (цветной бейдж).
   * Взаимодействие: тап по карточке открывает быстрое меню действий (изменить / удалить), дополнительно поддерживается жест свайпа влево.
   * Поиск продуктов в чистом Tailwind-дизайне.

### Фаза 2: Шторка добавления продукта с пресетами срока годности
1. **Базовый компонент шторки (`BaseBottomSheet.vue`)**:
   * Мобильная шторка с затемнением, плавной анимацией выезда снизу и закрытием по свайпу вниз или тапу на оверлей.
2. **Форма добавления (`AddProductSheet.vue`)**:
   * Поле ввода названия с автодополнением канонических ингредиентов.
   * Выбор категории ингредиента из существующих в системе.
   * Быстрые чипы срока хранения:
     * «+3 дня» (скоропортящееся: мясо, рыба, открытое молоко).
     * «+7 дней» (1 неделя: овощи, сыр, колбаса).
     * «+14 дней» (2 недели: яйца, йогурты).
     * «В заморозку» (+3 месяца).
     * «Своя дата» (открывает нативный календарь `<input type="date">`).
   * Выбор единиц измерения (шт, г, кг, мл, л) или приблизительного объема («мало», «средне», «много»).

### Фаза 3: Каталог рецептов и детальный экран
1. **Каталог (`RecipesView.vue`)**:
   * Существующие быстрые фильтры («Все», «🔥 Спасает продукты», «Легко», «Быстро»).
   * Карточки блюд с крупным процентом совпадения ингредиентов («95% продуктов есть», зеленый бейдж).
   * Время приготовления и сложность.
2. **Детальный экран рецепта (`RecipeDetailView.vue`)**:
   * Главное фото с градиентным наложением.
   * Информационный блок: время, сложность, порции (степпер порций), бейдж «Спасает продукты».
   * Интерактивный чек-лист ингредиентов:
     * Зеленая отметка: есть в наличии дома.
     * Кнопка «+»: добавить недостающий ингредиент в список покупок в один тап.
   * Крупная кнопка «Начать готовить» для перехода в полноэкранный Cook Mode.

### Фаза 4: Экран готовки (Cook Mode) с кухонным таймером
1. **Отдельный маршрут (`/recipes/:id/cook`)**:
   * Полноэкранный высококонтрастный темный интерфейс (`#0F172A` / `#022C22`), удобный для чтения на расстоянии вытянутой руки на кухне.
   * Сохранение состояния таймера в Pinia-сторе (время не сбрасывается при случайном выходе или возврате назад).
2. **Интерактивные элементы**:
   * Гигантский цифровой дисплей таймера (крупные цифры, кнопки Старт / Пауза / Сброс, регулировка минут).
   * Звуковой сигнал и вибрация (Web Vibration API) по окончании отсчета.
   * Пошаговая навигация рецепта («Шаг 1 из 5», крупный текст инструкций, кнопки «Следующий» / «Предыдущий» шаг).

### Фаза 5: Список покупок, Профиль и общие диалоги
1. **Список покупок (`ShoppingView.vue` и `ShoppingItemCard.vue`)**:
   * Прогресс-бар покупок («Собрано 4 из 10»).
   * Быстрое вычеркивание тапом по чекбоксу с плавной анимацией.
   * Действия с позицией: перенос в холодильник («В холод.») и удаление через контекстные кнопки или свайп.
   * Быстрое добавление позиции с автокомплитом.
2. **Профиль пользователя (`ProfileView.vue`)**:
   * Настройки исключений/аллергенов (чипы выбора).
   * Базовая корзина (соль, сахар, масло).
   * Индикатор синхронизации с облаком и статус PWA.
3. **Авторизация (`LoginView.vue`, `RegisterView.vue`)**:
   * Чистая форма авторизации в единой изумрудной палитре.

### Фаза 6: Полная верификация отказа от Vant UI, аудит бандла и отчет
1. **Статический поиск остатков Vant**:
   * Поиск по всему `frontend/src`: поиск строк `van-`, `from 'vant'`, `@import 'vant'`.
   * Результат строго равен **0**.
2. **Деинсталляция пакета**:
   * Выполнение `bun remove vant`.
   * Удаление любых ссылок на стили Vant в `main.ts` и `index.html`.
3. **Проверка компиляции и типов**:
   * Прогон `bun run type-check` (`vue-tsc --noEmit`) — 0 ошибок типизации.
4. **Прогон тестов**:
   * Прогон `bun run test` (`vitest run`) — 100% тестов проходят успешно (все 89 тестов адаптированы к новым компонентам).
5. **Тестовая сборка и аудит бандла**:
   * Прогон `bun run build` — успешная генерация продакшен-бандла Vite, фиксация уменьшения размера результирующего бандла.
6. **Обновление и компактификация документации (`README.md`)**:
   * Актуализация версии приложения по SemVer (`v0.9.0`).
   * Замена упоминаний Vant UI на Tailwind CSS + Lucide Icons.
   * Компактификация структуры README: лаконичное описание проекта, быстрый старт, чистая таблица сервисов без лишнего дублирования.
7. **Итоговый отчет о проделанной работе для пользователя**:
   * Детальная сводка: что добавлено (новые Tailwind-компоненты, токены, сторы), что изменено (экраны, логика взаимодействия), что удалено (компоненты Vant, стили, зависимости).
   * Пошаговый чек-лист ручной проверки в PWA/браузере (все пользовательские сценарии от добавления продукта до режима готовки).

## 5. Зафиксированные решения разработчика (Builder Decisions)
* **Cook Mode роутинг**: выделен отдельный маршрут `/recipes/:id/cook` с сохранением таймера в Pinia-сторе.
* **Карточки продуктов**: приоритет — надежный тап с открытием меню действий, дополненный плавным жестом `useSwipe`.
* **Микроанимации**: модальные окна и шторки анимируются средствами Vue `<Transition>` (`enter-active-class="transition duration-200 ease-out"`).
* **Вибрация**: проверка поддержки `navigator.vibrate` перед вызовом тактильного отклика.
* **Стор уведомлений**: легкий реактивный стор `useToast` (очередь тостов с автоскрытием через 3 секунды).
